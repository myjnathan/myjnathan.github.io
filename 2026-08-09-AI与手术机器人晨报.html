AI 与手术机器人晨报｜2026-08-09 ​

主题：别只优化一个总分——把可执行动作、物理残差与局部置信度写进闭环

信息窗口：2026-08-06 至 2026-08-09（北京时间）。8 月 9 日为周日，arXiv 最新公开批次仍是 8 月 7 日；本期因此不重复昨天已报道的论文，而是深挖同一批次中六项尚未覆盖、但对 AI Native、远程操作和机器人学习更有工程价值的工作。近 72 小时未检索到可由监管机构、医院或厂商原始公告核验的新远程手术临床里程碑或手术机器人产品/监管决定。以下论文多为预印本，作者结果尚待同行评议、独立复现和医疗场景验证。

今日摘要 ​

  1. Agent 的能力不只在模型权重里，也在 prompts、工具、控制流、记忆与评测组成的 harness 里；但“自动优化 harness”本身仍容易过拟合可见分数。 HarnessOpt-Bench 在固定预算和隐藏测试集下评估 5 个前沿模型、4 类任务、111 次运行，发现模型差异通常大于其所用 coding harness 的差异，原生 harness 也不稳定占优；搜索期间看到的最佳验证分数往往高于最终隐藏测试分数。
  2. 物理系统不能只给 Agent 一个总分。 OPERA 将可执行操作、可解释物理残差、可见优化分数和离线真实物理表现分离；在三类光学任务中，仅给分数时有 23.6%–39.0% 的决策“分数上升但物理没有改善”，加入逐通道残差后降至 0.9%–1.9%。
  3. 远程操作的瓶颈不只在网络，也在人机接口把多少控制负担留给操作者。 一项 20 人、英国到意大利的机械臂遥操作实验中，触屏路径输入相对 Xbox 摇杆把中位完成时间从 5.38 分钟降至 2.50 分钟，并降低越界和 NASA-TLX；但任务是静态表面采样，参与者多数已有机器人/控制器经验，不能外推为手术控制台结论。
  4. 触觉闭环最值得优化的不是平均吞吐，而是确定性尾延迟。 一套 FPGA 近传感计算流水线以固定 0.211 ms 重建 128×128 接触深度，并把保护反射闭环从主机方案的 169.9±27.8 ms 缩短到 28.3±4.9 ms；这提示远程手术的安全反射应尽量在患者侧闭合。
  5. 传感器位置也可以成为控制变量。 Sliding Sensors 在连续体机器人内部主动滑动一个微型位姿传感器，使高置信区域随任务关注点移动；整体形状误差改善有限，但它把“哪里必须知道得更准”从固定硬件选择升级为运行时策略。
  6. 跨机器人学习应共享动力学先验，而不是强行共享动作语义。 DyPES-VLA 用未来预测学习跨形态共享的物体运动/接触表征，再用设备特异的 MoE action head 输出各机器人原生控制量。其结果很强，但真实实验只覆盖三类桌面操作、每任务每设备 25 次 rollout，离手术接触安全仍很远。
  7. 交叉结论：需要统一的是证据接口，不是所有控制表示。 Agent harness、光学实验、遥操作、触觉前端、连续体状态估计和跨形态 VLA 都在指向同一设计：把可共享的目标/物理证据放在上层，把设备特异执行、局部安全反射和置信边界留在下层，并用隐藏评测或独立测量阻止系统只“优化看得见的分数”。

AI 前沿 ​

1. HarnessOpt-Bench：把 AI Native 的“改工作流”变成受预算约束的隐藏评测 ​

事实。 HarnessOpt-Bench 把 harness 定义为围绕模型的 prompts、工具、控制流、上下文、记忆和编排代码。优化器拿到一个 seed harness、开发集逐例反馈、验证集汇总分数和固定评测预算，可以直接修改整个 harness 代码库；隐藏测试集始终不可见，候选版本、模型调用和预算消耗由可信执行环境记录与约束。论文原文｜HTML 全文

作者结果与观点。 团队在 4 个下游任务上进行了 111 次计分运行，比较 5 个前沿优化器模型在共享 coding harness 与各自原生 harness 下的表现。作者报告：共享 harness 下的模型差异平均大于共享/原生 harness 的差异，原生 harness 没有一致优势；优化器在搜索中看到的最佳验证分数通常高于最终候选的隐藏测试分数。详细 trace 在 111 个运行单元中只被 7 个单元请求 16 次，阅读评测输出的动作占比还与收益呈 -0.31 至 -0.64 的相关。

边界。 这不证明 trace 无用：逐例摘要可能已经足够定位当前任务的问题，也可能是模型不会有效使用长 trace。四个 seed 中有一个是不可工作的 stub，另外三个也刻意保留明显优化空间；结果不能直接等同于成熟生产系统的自我改进能力。验证—测试差距也无法区分选择性过拟合与数据分布差异。

推断。 对 Nathan 的 AI Native 工作流，真正可迁移的是评测边界：允许 Agent 改 prompt、skill、memory 和 orchestration，但不允许它改 verifier、隐藏任务或预算计量。晨报、代码自动化和 PAI workflow 都应至少保留一个从不参与调参的回放集；否则“自动优化”很容易变成对当前可见样例的自动迎合。

2. OPERA：总分不能告诉 Agent 物理上哪里仍然不对 ​

事实。 OPERA 把光学实验的接口拆成三层：类型化、检查过的可执行 operator；由实时观测计算的物理 residual；以及两个彼此隔离的评价层——Agent 可见的优化分数与只用于离线评估的隐藏物理参考。团队在光束整形、结构光三维重建和干涉测量上，用 4 个工具调用语言模型进行数字孪生决策，并把冻结后的 protocol 转移到三套真实光学仪器。论文原文｜HTML 全文｜代码

作者结果。 在 90 个独立问题、7,486 个有效决策中，仅分数反馈造成“分数上升但离线物理表现未改善”的比例为 23.6%–39.0%，逐通道 operator–residual 反馈降至 0.9%–1.9%。在另外 270 个测试问题中，OPERA 达到并保持目标的比例为 75.8%，四种参考策略为 33.9%–60.1%；预算消耗为上限的 61.7%，参考策略为 70.8%–86.0%。结构光硬件主配置中，转移 protocol 平均使用 60.0% 的投影预算，固定 Gray code 使用 95.8%。

交叉核验与边界。 这与 HarnessOpt-Bench 的隐藏测试结论从两个独立方向一致：系统必须有优化器看不见、改不了的独立真值层。OPERA 的主要决策实验仍在数字孪生中；硬件 transfer 冻结了 protocol，硬件 residual 没有在线返回给 Agent，因此尚未证明语言模型在真实仪器闭环中能维持同样可靠性。其相对强算法基线的优势主要集中于分布偏移，熟悉条件下并不总优于固定规则或任务特定方法。

推断。 远程手术的高层 AI 不应只看到“轨迹误差”“任务成功率”或综合安全分。应把残差按物理含义拆开，例如 tip_position / contact_force / RCM_error / network_age / actuator_saturation / tissue_motion，保留方向、单位、阈值和更新时间；决定能否执行的确定性安全层与离线风险审计必须独立于模型。

手术机器人与远程手术 ​

1. 触屏遥操作：减少命令链可能比更熟练地拨摇杆更有效 ​

事实。 研究在 Bristol Robotics Laboratory 招募 20 名参与者，通过远程链路控制意大利 IIT 的机械臂完成矩形和正弦路径表面采样，比较 Xbox 摇杆、触屏路径界面和已知静态任务的一键自动回放。20 人中 19 人有机器人经验，18 人自报熟悉控制器或模拟器。论文原文｜HTML 全文

作者结果。 触屏相对摇杆把中位完成时间从 5.38 分钟降至 2.50 分钟；180 秒内完成比例从 45% 升至 75%。正弦路径覆盖率从 84.1% 提高到 90.7%，矩形任务的额外越界面积从 17.3% 降至 4.2%。NASA-TLX 均值从摇杆的 52 降到触屏的 43，一键自动模式为 31。

边界。 样本小且偏向技术熟练者；任务静态、可视、无组织接触和紧急恢复，一键模式更是作者明确设置的认知负荷下界，不是可部署方案。论文没有把网络时延、抖动或丢包作为独立变量，也没有外科医生参与，因此不能据此选择手术主控接口。

推断。 对远程手术，更值得做的不是“触屏替代主手”，而是把不同时间尺度的意图分层：高频精细操作仍由主从映射承担，低频路径、视角、禁入区或回撤意图可由直接操控改为监督式输入。评测必须同时覆盖完成时间、越界、力峰值、恢复时间、信任校准和 NASA-TLX，而不是只比较轨迹 RMS。

2. Near-sensor Computing：患者侧安全反射需要确定性尾延迟 ​

事实。 该工作把视触觉传感器的 photometric stereo 与 Poisson 深度重建做成 Xilinx Zynq UltraScale+ FPGA 上的全流式流水线，不等待完整帧、不依赖输入相关迭代。128×128 输入在 166 MHz 下固定经过 35,107 个周期后输出首个深度值。论文原文｜HTML 全文

作者结果。 1,000 帧测量中每帧重建延迟均为 0.211 ms；同一算法的 99 分位延迟在桌面 CPU、RTX 4090 D 和 Jetson Orin NX 上分别达到 0.93、0.43 和 5.3 ms。15 种接触几何的深度误差为峰值接触深度的 0.17%。基于片上结果的机器人保护反射闭环为 28.3±4.9 ms，等价主机处理闭环为 169.9±27.8 ms。重建核心逻辑估算功耗 347 mW，但完整 FPGA 原型估算约 4.18 W。

边界。 这是特定视触觉传感器、特定 Poisson 重建和单一保护反射的实验；0.211 ms 不含完整相机曝光、执行器响应、触觉封装、网络或手术系统总时延。功耗部分同时混合了仿真估计与实测平台边界，不能直接比较成产品级能效。

推断。 对 Nathan 的远程手术链路，真正重要的是架构位置：触觉重建、限力、碰撞撤退等高频保护应尽可能在患者侧形成有上界的确定性闭环，远端网络承载操作者意图和低频策略更新。系统指标应从平均 RTT 扩展为 sensor-to-reflex p99.9、最坏调度抖动和断网后的本地安全行为。

3. Sliding Sensors：主动移动“可信区域”，而不是追求整条机器人同样精确 ​

事实。 Sliding Sensors 在 70 cm 长的腱驱连续体机器人中央通道内，用线性机构滑动一个直径 0.5 mm、长度 8 mm 的 5-DoF 电磁位姿传感器，并把随时间变化的测量位置作为 factor graph 的测量因子。原型行程 60 mm，实验以 24 mm/s 往返三次。论文原文｜HTML 全文

作者结果与观点。 高置信状态估计区域会跟随传感器位置移动；在静态/准静态形态下，往返滑动相对固定在末端的单传感器，位置误差最多降低 8.4%，姿态误差最多降低 3.8%。作者强调的目标不是让全身误差统一最小，而是把足够高的置信度放到任务相关位置。

边界。 精度收益很小，且只验证静态和准静态状态；传感器动态、滑动频率、摩擦、通道占用、灭菌与真实组织环境均未验证。它与腔镜或导管机器人结构相关，但不是手术任务实验。

推断。 这为连续体手术机器人提供了一个很实用的观念：region of interest 可以驱动 sensing policy。当远程操作者接近接触区、弯折区或遮挡区时，系统主动把有限感知资源移到该处；安全约束则使用局部置信区间，而不是把整条形状估计压缩成一个平均误差。

4. DyPES-VLA：共享接触与场景变化，保留设备原生控制语义 ​

事实。 DyPES-VLA 先用无动作标注的人类/机器人视频做未来帧预测，使共享 query states 学到物体运动、接触和交互后场景变化；再在多机器人示教上联合训练。共享 attention 建模动作时序，设备特异 MoE expert、encoder 和 decoder 则直接输出每种机器人原生动作空间，不要求手工对齐成统一动作向量。论文原文｜HTML 全文｜项目页

作者结果。 单一 checkpoint 在 LIBERO、RoboCasa-GR1、RoboTwin 2.0 上分别报告 98.0%、59.25%、89.02% 成功率。真实环境使用 FR3 单臂、COBOT Magic 双臂和 Unitree G1 三种形态、三项桌面任务，每个任务—设备组合 25 次 rollout；联合微调后的单一策略平均成功率为 75.6%，对比联合微调 GR00T-N1.6 的 59.6%。去掉未来预测目标，在三个仿真基准上分别下降 1.9、2.5、2.35 个百分点；换成共享 dense action head 下降 1.2–2.1 个百分点。

边界。 这是作者自报的预印本结果，真实任务只有放水果、倒水、放书，G1 上三项成功率仍只有 72%、52%、36%。策略不使用 proprioception，未来接触只通过线性 probe 证明“可解码”，不等于具备安全接触控制。数据、计算与模型规模也很大，训练使用 16 张 H100。

推断。 对手术机器人学习，更合理的数据架构可能是：共享层学习组织/器械的视觉变化、接触阶段与任务语义；设备层保留主从映射、运动学、控制频率、力限幅和器械语义。不要为了构建“大一统动作数据集”而抹平不同设备的控制边界。跨设备迁移的首要验收也应是接触事件、约束满足与失败恢复，而不是通用桌面成功率。

论文 / 产品 / 监管动态 ​

论文 ​

  • AI Native： HarnessOpt-Bench 把 harness 自优化变成带隐藏测试集、可信执行边界和固定评测预算的系统任务。
  • 物理 Agent： OPERA 证明逐通道、带单位和物理含义的 residual 比单一总分更能抑制 specification gaming。
  • 远程操作人因： 触屏路径界面在小样本表面采样任务中显著降低时间、越界与认知负荷，但尚未进入手术或受控网络条件。
  • 触觉边缘计算： FPGA 近传感重建把可变调度延迟变成固定周期，并显著缩短保护反射闭环。
  • 连续体机器人： Sliding Sensors 将传感器位置变成主动感知自由度，使局部高置信区域可随任务移动。
  • 机器人学习： DyPES-VLA 把跨形态共享动力学与设备特异动作解码分开，为异构机器人数据提供更合理的层次边界。

对 Nathan 当前项目的启示 ​

1. 远程手术：先定义 residual contract，再讨论高层 AI ​

为每个可执行操作定义输入、权限、超时、幂等性和硬约束；为每个残差定义物理含义、单位、方向、阈值、采样位置、更新时间和失效行为。综合分只能用于展示，不能替代底层 residual。

最小实验与完成标准： 在现有回放中选取 RCM 偏差、力超限、网络数据年龄、驱动饱和四类残差，分别注入单一和组合异常。高层策略可以选择恢复动作，但确定性层必须在所有用例中阻止越界；离线审计使用模型不可见的真实传感器/台架参考判断“指标改善是否对应物理改善”。

2. 患者侧边缘：建立本地反射的时延预算与断网契约 ​

把安全闭环拆为 sensor exposure → reconstruction → residual → safety decision → actuator response，逐段测量而不是只报端到端平均值。网络仅传递操作者意图，不能成为接触保护的必经路径。

完成标准： 报告每段的 p50/p99/p99.9、最坏连续丢帧和总反射上界；断网、远端进程卡死或时钟漂移时，患者侧仍在既定时间内进入保持、限力或安全撤退状态。

3. 机器人强化学习：共享任务证据，隔离设备动作空间 ​

先定义跨设备共享的 episode schema：场景、器械、接触事件、组织变化、目标与残差；各机器人保留独立的运动学、动作频率、限幅、控制模式和安全回退。共享表示与设备控制头分别训练、分别验收。

完成标准： 同一接触阶段分类/未来接触预测能跨至少两个仿真设备迁移；设备 A 的 action decoder 不得被设备 B 数据直接调用。迁移增益必须在隐藏任务和一个未参与调参的 phantom 轨迹上成立，并同时报告成功率、峰值力、约束违反与恢复率。

4. AI Native：自动优化只能改候选系统，不能改裁判 ​

把 prompt、skill、memory、tool policy 和 orchestration 视为可优化 harness；把任务划分、verifier、预算、敏感数据边界与最终发布门放在不可写区域。保存每个候选的版本、评测成本和被选原因。

完成标准： 建立 dev / validation / hidden replay 三层集合；连续三次自动优化中，只在 hidden replay 同样改善才升级。若验证分升而隐藏分不升，自动回退且记录为 selection overfitting，而不是继续堆 prompt。

5. 遥操作人因：把“监督式输入”作为低频通道单独验证 ​

不更换现有高频主从控制，先在视角调整、禁入区、回撤路径或器械交接中加入低频直接操控/监督式输入，比较它是否真正减少认知负担。

完成标准： 同一批操作者交叉完成传统与监督式条件；同时报告 NASA-TLX、完成时间、越界、力峰值、异常发现时间和接管恢复。自动化降低负荷但延迟异常识别时，不得判定为改进。

值得继续跟踪的问题 ​

  1. Harness 优化中，怎样让 Agent 读取少量高信息 trace，而不是只看逐例分数或把上下文耗在原始日志上？
  2. 可见验证分持续乐观时，如何区分选择性过拟合、评测噪声与真实分布偏移？
  3. OPERA 的 residual contract 能否在真实硬件在线闭环中保持同样收益，而不是只迁移冻结 protocol？
  4. 手术场景里哪些 residual 必须由独立传感器测量，哪些可由模型估计？模型估计的残差可否参与硬安全门？
  5. 触觉近传感计算加入曝光、光源、执行器和系统总线后，完整 sensor-to-reflex 尾延迟是多少？
  6. 局部安全反射和远端操作者命令冲突时，控制权切换如何被感知、解释和回放？
  7. 连续体机器人主动移动传感器会不会引入新的摩擦、迟滞和故障模式，抵消置信度收益？
  8. 怎样根据当前手术阶段实时选择“哪里必须知道得更准”，并把感知资源调度纳入安全证明？
  9. 跨设备 VLA 的共享表示如果能预测未来接触，是否也能校准接触时间与不确定度，而不是只做二分类 probe？
  10. 设备特异 action head 如何与确定性 RCM、力限幅和网络失效状态机组合，而不让学习策略绕过安全层？
