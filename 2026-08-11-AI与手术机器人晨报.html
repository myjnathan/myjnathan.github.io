AI 与手术机器人晨报｜2026-08-11 ​

主题：更新不是追加——让记忆、技能、控制权与策略都能被撤销和重新校准

信息窗口：2026-08-08 至 2026-08-11（北京时间）。arXiv 在周末后于 8 月 10 日公布新批次；本期优先选择该批次中对 AI Native、机器人学习和远程手术系统架构有直接工程价值的工作。论文 v1 多在 8 月 7 日提交，均为预印本，尚待同行评议、独立复现与医疗场景验证。近 72 小时未检索到可由监管机构、医院或厂商原始公告核验的新远程手术临床里程碑或手术机器人监管决定。

今日摘要 ​

  1. 长期运行系统的关键能力不是“记得更多”，而是能让旧状态失效。 TEPA 把 Agent 记忆显式分成 Hypothesis / Active / Revoked；在隐藏规则完全反转时，追加式记忆和 last-write-wins 的成功率都跌到 0.210，低于无记忆的 0.309，而带撤销的记忆达到 0.950。
  2. AI Native 的 skill 也需要垃圾回收。 SkillProx 不直接相信模型写出的“经验补丁”：先在同一任务批次重跑并回滚退化，再用冻结的 leave-one-out utility audit 删除低贡献知识单元。它在三个表格任务基准、三个 Qwen 主干上取得更稳定的增益，但证据仍局限于表格问答与少量随机种子。
  3. 机器人接管不是单阈值异常检测，而是两个方向、两套证据的状态机。 AutoIntervene 用局部视觉—动作支持度决定“策略何时交权”，用全局支持度决定“操作者恢复后何时还权”；七项双臂任务两轮适应后平均成功率从 30.9% 提升到 80.0%，高于人工按钮切换的 68.6%。
  4. 学习系统不同层的更新速度不应相同。 TEMPO 冻结视觉语言主干，慢更新语义投影、快更新动作专家；CALVIN 五步链成功率从 FLOWER 的 77.8% 提升到 81.7%，而 1:1 同频更新只有 77.7%。收益不大，但消融直接支持“语义慢、动作快”的设计。
  5. 手术机器人学习仍首先缺可控真值，而不是更复杂的网络。 华盛顿大学团队为 RAVEN II 建立六电机—拉索外力加载台，在机器人运动时施加任意方向外力，X/Y/Z 轴平均绝对误差分别为 0.80/0.79/0.44 N，为无末端传感器的力估计提供可重复训练数据基础。
  6. 交叉结论：可持续闭环必须同时拥有四个动作——激活、撤销、接管、恢复。 TEPA 与 SkillProx 从 Agent 侧证明“只追加”会污染上下文；AutoIntervene 与 TEMPO 从机器人侧证明不同状态和方向需要独立门限与时间尺度。对远程手术而言，版本、控制权和学习更新都应成为可审计状态，而不是一次写入后永久生效。

AI 前沿 ​

1. TEPA：长期记忆必须有“撤销”状态 ​

事实。 TEPA 将每条记忆表示为带冲突键、取值、支持/冲突计数、生命周期状态和时间戳的 precedent。普通检索只读取 Active；同一键出现足够反证后，旧 precedent 移入 Revoked 档案而不再进入 prompt。带执行验证的 TEPA-Full 还在候选记忆激活前做支持、反事实和污染三类试验。论文原文｜HTML 全文

作者结果。 在 50 个随机种子的受控隐藏规则漂移中，完整反转阶段 append-only 与 last-write-wins 成功率均为 0.210，无记忆为 0.309，TEPA 为 0.950；真实文件读写/工具执行版本分别为 0.203、0.298 和 0.950。偏好更新流中 append-only 只有 0.138，无记忆 0.837，TEPA-Full 0.872。外部 MemoryAgentBench 单跳任务中，TEPA 与强 last-write-wins 都为 0.890。

边界。 主要漂移实验使用确定性执行器与结构化冲突键，证明的是内存状态机，不是通用 LLM 自主判断。TEPA 在多跳 MH-6k 上降到 0.040，在 262k 长上下文单跳设置降到 0；开放式记忆如何抽取“什么与什么冲突”仍未解决。

推断。 Nathan 的 PAI 已有 inbox → warm → cold → archive 生命周期，但运行时检索还应显式维护 active / superseded / review_due。当 NOW.md、项目状态或偏好更新时，旧记录不能仅靠时间排序被“挤下去”，而要留下 superseded_by、证据和失效日期；公开内容生成默认只读 active 状态，archive 只用于审计。

2. SkillProx：Agent skill 的自我改进需要重跑、回滚和压缩 ​

事实。 SkillProx 把 skill 视为可优化的文本程序。前向阶段依据失败诊断编辑 skill，在同一任务批次重新执行，退化则回滚，并把实测结果反馈给下一轮诊断；后向阶段把 skill 拆成可审计知识单元，用冻结的 leave-one-out utility audit 估计贡献，再由验证集门控保留、降级或删除。论文原文｜HTML 全文

作者结果。 在 SpreadsheetBench Verified 上，SkillProx 将人工初始 skill 的准确率从 38.3% 提升到 51.3%（Qwen3.5-27B），从 36.7% 提升到 54.5%（Qwen3.6-27B）；相较最强 gradient-based baseline，论文报告平均提升 3.0 个百分点。阈值扫描中，删除 41.5% skill 内容仍把准确率从无压缩的 50.3% 提到 52.0%；删除超过约 80% 后才明显下降。

边界。 训练/验证/测试按 2:1:8 划分，每个设置最多 30 轮交互，三个模型各只有三个训练种子；任务集中在 spreadsheet 与表格问答。对代码库、医疗知识或多工具工作流，知识单元之间的依赖可能无法由 leave-one-out 准确衡量，删掉“平时无用、极端状态关键”的安全规则尤其危险。

推断。 AI Native workflow 不应允许 Agent 直接把一次失败总结追加到全局 skill。更稳妥的发布链是：候选 patch → 失败样例重跑 → 隐藏回放 → 与原版本比较 → 原子化变更 → 依赖检查 → 人工/策略门 → 可回滚发布。安全规则和隐私边界应标记为不可由 utility 压缩删除。

手术机器人与远程手术 ​

1. AutoIntervene：接管与还权必须分别校准 ​

事实。 AutoIntervene 面向 action-chunking 模仿学习策略，使用成功执行构建视觉—动作支持记忆。策略控制时，以当前任务阶段的局部支持判断是否交给操作者；人工控制时，策略在后台继续提案，以全局支持判断何时恢复自主。两个方向分别用 held-out expert demonstrations 的经验分位数校准阈值，并要求连续两次判定一致，形成滞回。论文原文｜HTML 全文｜项目页与视频

作者结果。 七项真实双臂操作任务中，每个任务—方法用 25 次无辅助物理 rollout 评估。初始策略平均成功率 30.9%；两轮适应后，人工按钮切换为 68.6%，AutoIntervene 为 80.0%，额外 operator-control time 平均分别为 179.9 秒和 122.9 秒。受控接管测试仅含 10 次扰动与 10 次正常 rollout，AutoIntervene 的 cut-in/cut-out precision 与 recall 均为 1.00，正常条件误触发率为 0；去掉视觉支持后完全漏掉位移，去掉动作风险后还权 precision/recall 都降到 0.56。

边界。 任务是固定实验室中的双臂整理、折叠与装箱，不含组织形变、器械碰撞、网络延迟或临床操作者。阈值来自专家示教分布，受控接管样本很小；系统识别的是“是否仍在成功示教支持域”，不是严格的安全性或因果失败预测。

推断。 远程手术的控制权协议不应是单一 confidence < x。至少拆成 remote surgeon → local safety/shared autonomy 与 local safety/shared autonomy → remote surgeon 两个方向：前者依据数据年龄、力/RCM 残差、视频质量与动作支持；后者还必须确认恢复动作已完成、操作者输入稳定、网络窗口恢复并持续若干周期。每次切换记录原因、证据快照和滞回计时器。

2. TEMPO：语义慢更新、动作快更新 ​

事实。 TEMPO 冻结预训练视觉语言主干，只在线优化语义投影层和低层动作专家。两者使用独立 TD3 loop：语义投影低频更新以限制 latent-action drift，动作专家高频更新以吸收实时控制反馈。论文原文｜HTML 全文

作者结果。 CALVIN ABC→D 五步任务链中，TEMPO 的 SR5 为 81.7%、平均完成链长 4.59；基础 FLOWER 为 77.8%/4.49，单 loop FLOWER-RL 为 78.4%/4.51。动作:语义更新频率为 5:1 和 10:1 时 SR5 分别为 81.7% 与 81.2%，1:1 同频更新为 77.7%。真实平台只验证抽屉内滑块与小车取出两项任务，每项 60 条示教、三个随机种子，每个 checkpoint 20 次评估；作者仅以曲线和示例说明后期 reward 更高，没有给出可直接比较的最终成功率表。

边界。 仿真提升约 3–4 个百分点，真实任务少且奖励稀疏；语言语义与动作控制的模块边界是模型设计预设，不代表手术阶段语义天然可被稳定分离。论文未评估约束违反、力峰值、干预频率或分布外安全。

推断。 手术机器人 RL 可将稳定知识与快速适应分开：器械语义、手术阶段和禁区定义慢更新；设备动力学残差、视觉偏差和局部动作策略快更新；RCM、力限和急停不进入可学习更新。部署门应分别审查“语义是否漂移”和“动作性能是否改善”，不能用一个总 reward 共同放行。

3. RAVEN II 外力加载台：先造出可控真值，再训练无传感器力估计 ​

事实。 华盛顿大学团队在 RAVEN II 工作空间周围安装六套电机—卷线轮—拉索—load cell 单元，全部连接末端；控制器根据末端位置和拉索方向用 SLSQP 求各拉索目标张力，并设置力指令与张力两个反馈层。load cell driver 以 320 Hz 工作。论文原文｜HTML 全文

作者结果。 初步轨迹数据中，外力加载相对目标值的 X/Y/Z 平均绝对误差为 0.80、0.79、0.44 N。系统目标不是直接成为术中传感器，而是在机器人遍历工作空间时施加方向和幅值可控的外力，为仅依靠关节/电机状态的末端力估计模型生成 ground truth。

边界。 这是一套初步研究台，论文尚未训练或评估力估计网络，也未报告带宽、动态相位误差、全工作空间条件数、拉索互扰或与真实组织接触的分布差距；约 1 N 的加载误差是否足以支持精细组织力估计尚不确定。

推断。 对 Nathan 的远程手术项目，训练“无末端传感器力估计”前应先定义数据设施验收：外力方向覆盖、幅值分桶、末端位姿/速度覆盖、加载动态带宽、重复性、温漂和盲测轨迹。仿真或人工按压数据只能作为补充；没有可追溯 ground truth 的模型精度不应进入触觉反馈或安全门。

论文 / 产品 / 监管动态 ​

论文 ​

  • Agent memory： TEPA 将失效从“检索排序问题”改造成显式生命周期状态；有效范围目前主要是结构化单键冲突。
  • AI Native skills： SkillProx 用执行重跑和 utility-aware shrinkage 抑制自演化 skill 的错误累积与上下文膨胀。
  • 人机共驾： AutoIntervene 证明策略→人工与人工→策略需要不同证据、阈值与滞回。
  • 机器人强化学习： TEMPO 的两时间尺度 post-training 给出“稳定语义层、快速动作层”的可检验实现。
  • 手术机器人数据： RAVEN II 外力加载台把“代表性外力训练数据”从手工采样变成可编程实验设施。

产品与监管 ​

近 72 小时没有检索到足以扩写的手术机器人产品、监管或远程手术临床新进展；AI 官方技术发布同样稀少。本期刻意缩短新闻部分，把篇幅留给可迁移的系统机制。

对 Nathan 当前项目的启示 ​

1. PAI / AI Native：给所有可积累对象统一生命周期 ​

将 memory、skill、workflow rule 都表示为带 id / key / version / state / evidence / superseded_by / rollback 的对象，默认检索只读 active；冲突内容进入 revoked/archive，但保留来源与复盘证据。

最小实验与完成标准： 从 PAI 选 20 条会变化的项目/偏好记录，构造 stable → reversal → return 回放。新事实出现后，旧值必须在一次更新周期内退出普通检索；所有撤销可追溯，恢复旧值时只能 re-promote 新版本，不能偷偷“取消删除”。

2. 远程手术：把控制权切换实现为双向滞回状态机 ​

定义 REMOTE_CONTROL / LOCAL_GUARD / LOCAL_RECOVERY / HOLD，分别配置进入和退出条件。切入安全态的证据与恢复远程控制的证据必须不同，且都要求连续窗口稳定。

完成标准： 在回放台注入时延突增、视频冻结、力估计漂移、RCM 超限和远端进程卡死。每次异常在规定上界内切入正确状态；恢复不能发生抖动；日志能回答“谁在何时、基于什么证据取得/归还控制权”。

3. 机器人强化学习：建立三时间尺度更新预算 ​

  • 毫秒级：确定性安全控制与限幅，只接受已验证参数更新。
  • 秒到分钟级：设备特异动作策略和残差补偿，可用在线/近线数据快速更新。
  • 天到周级：任务语义、阶段定义、memory 与 skill，经隐藏回放和人工审查后发布。

完成标准： 任一层更新都不能越权修改更稳定层的约束；动作性能提升但语义回放退化时拒绝发布；所有模型与阈值可一键回滚到上一已验证版本。

4. 力学习：先把 ground-truth rig 做成数据产品 ​

不要先选网络结构。先定义外力加载装置或等价标定流程的覆盖矩阵、时间同步、校准、质量门和版本规范，再生成训练/验证/盲测集合。

完成标准： 数据集按位置、方向、幅值、速度与温度分层；盲测轨迹不参与调参；模型同时报告 MAE、95/99 分位误差、动态相位、跨日漂移和超出训练支持域的拒绝率。

5. 自动化发布：候选改进必须可撤销 ​

晨报、代码修改和 workflow 自优化都采用 candidate → replay → diff → publish → observe → rollback。一次成功不能自动升级为长期规则，一次失败也不应把全局记忆清空。

完成标准： 每次 skill/memory 变化都能定位对应失败样例与验证结果；隐藏回放无改善则不升级；回滚不依赖重新生成旧文本，而是恢复已签名/哈希的上一版本。

值得继续跟踪的问题 ​

  1. 开放式记忆中的冲突键怎样抽取，才能避免把“观点演进”误判为“事实覆盖”？
  2. 一个旧规则在常规任务贡献很低、只在极端安全场景有价值时，utility audit 如何避免误删？
  3. 自动接管阈值跨操作者、器械、手术阶段和网络条件时是否仍能校准？需要按人、按阶段还是按风险等级分层？
  4. 远端操作者与患者侧安全控制同时发出相反命令时，控制权仲裁如何保证可解释、可回放且无抖动？
  5. TEMPO 的双时间尺度收益来自模块语义分工，还是仅来自更保守的优化超参数？能否在不同 VLA 架构复现？
  6. 在线 RL 更新动作专家时，如何保证 RCM、力限和网络失效状态机永远处于不可写边界？
  7. RAVEN II 外力加载台在动态轨迹、高频变化和工作空间边缘的实际带宽与误差是多少？
  8. 无末端传感器力估计跨器械、拉索张力、温度与磨损迁移时，怎样检测模型已经离开标定支持域？
  9. 远程手术日志能否统一表达 memory 版本、策略版本、控制权状态和物理 residual，形成一次事件的完整因果链？
