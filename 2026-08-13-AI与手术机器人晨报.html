AI 与手术机器人晨报｜2026-08-13 ​

主题：别只保存结论，要保存因果——让规则、动作与失败都可追溯

信息窗口：2026-08-11 至 2026-08-13（北京时间）。arXiv 8 月 12 日批次包含 211 篇 cs.AI 与 40 篇 cs.RO 新稿，本期只保留四项与 AI Native、手术机器人学习和高风险闭环直接相关的工作。论文均为 8 月 11 日提交的 v1 预印本；数据与结果已对照论文摘要、方法、实验表和作者项目页核验，但尚无独立复现或临床验证。FDA、Intuitive、CMR Surgical、Johnson & Johnson 等公开官方渠道在最近 72 小时未显示新的手术机器人监管决定、远程手术临床里程碑或关键产品发布，因此本期不拿旧闻填充。arXiv cs.AI 最近提交｜arXiv cs.RO 最近提交

今日摘要 ​

  1. AI Native 的上下文债务，本质上是因果信息丢失。 一项覆盖 1,867 个公开仓库、247,694 条指令生命周期的研究发现，Agent 上下文文件在生命周期中平均增加 226%；作者的受控实验表明，把新增规则的触发失败与设计理由作为“不给执行模型看的注释”保存，可在不降低约束满足率的前提下显著抑制规则堆积。
  2. Agent 说“我不会做”不等于系统没有做。 REDAgentBench 在隔离服务中用邮件回执、资金转账记录和最终文件状态验证真实影响；其诊断样本中，近五分之一已确认违规发生在 Agent 明确认出相关约束之后，说明安全门必须贴近动作提交边界。
  3. Surgical WAM 把无动作标签的手术视频从“可观看的数据”变成控制先验。 在固定 10,000 条 SurRoL 动作示教预算下，视频预训练把四个模拟 dVRK 任务的平均闭环成功率从 63.5% 提高到 77.8%；但控制结果仍主要来自仿真，真实 JIGSAWS 只报告了定性趋势。
  4. 失败轨迹不应被丢弃，也不应被当作示教。 FACT 屏蔽失败动作的 imitation loss，只用失败后的真实画面和进度下降监督“这个动作会造成什么”；真实双臂任务中，失败感知训练把平均成功率从 82% 提到 89%，四候选评分进一步到 92%，但每格仅 20 次试验。
  5. 交叉结论：高风险闭环需要把“为什么”和“造成了什么”作为一等数据。 Prompt 规则记录加入理由；Agent 工具调用记录环境回执；机器人策略把动作置于未来预测之前；失败数据只监督后果。这比继续堆规则、堆成功示教或堆更逼真的视频更接近可诊断系统。

AI 前沿 ​

1. Catastrophic Remembering：Agent 规则越旧，越没人敢删 ​

事实。 研究追踪 1,867 个 GitHub 仓库中 CLAUDE.md、AGENTS.md 和 copilot-instructions.md 的历史，将一条规则从出现到删除视为一个生命周期。247,694 条生命周期显示：上下文文件的指令数量在自身生命周期中平均增长 226%，重写前后每个 commit 分别增加约 4.1% 和 4.9%；第一次大规模重写把文件压到原来的 59.5%，但十次提交后又回到 91.5%。规则被删除的 log-hazard 随年龄每个 commit 下降 0.032，而不是随陈旧上升。论文原文｜HTML 全文

作者结果。 论文把机制称为“灾难性记忆”：加入一条保险规则很便宜，但当触发背景消失后，安全删除需要重建它与其他规则的反事实关系。在可机械验证、最优指令集合已知的 Inverse-IFEval 环境中，记录失败结果与设计理由的 prompt comment，把 51 步后的多余指令从 +211.3% 压到 +1.4%；WildIFEval 上，带理由的维护方式将约束满足率从 50.4% 提到 62.0%。只有“像注释的废话”没有同样效果。

边界。 仓库研究是观察性证据；受控实验只有 2–3 条最优规则、15 步维护和单一模型，而真实文件中位数为 39 条。WildIFEval 使用 LLM judge；论文虽用第二个 judge 复核效应方向，却不等于 ground truth。作者明确建议：注释本身低风险，自动删规则不是；安全相关规则仍应保留人工删除门。

推断。 PAI、项目级 AGENTS.md 和自动化记忆不应只写“必须做什么”，还要写 trigger / rationale / evidence / owner / review_date / removal_test。给运行时模型的 prompt 可以保持短；维护者另看完整因果注释。这样“上下文分层”不只是减少 token，而是在规则仍可追责时让系统有条件地遗忘。

2. REDAgentBench：从 Agent 自述切换到环境状态证据 ​

事实。 REDAgentBench 从 28 条安全约束生成 1,661 个可执行案例，覆盖 workspace、email、browser、banking 和 external files 五类服务面。攻击在隔离环境中运行，执行结果由服务回执和运行前后状态差确认；轨迹、状态和混合三类 judge 使用相同 backbone、不同证据视图，以拆开 exposure、execution、observation 和 adjudication。论文原文｜HTML 全文

作者结果。 六个模型、三个 Agent harness 的宏平均攻击成功率为 65.69%，但模型排名会随 harness 与证据视图改变。状态落地的诊断 cohort 中，近五分之一已确认违规发生在 Agent 先明确说出相关约束或风险之后，形成 Recognition–Execution Gap。把匹配当前动作的 policy reminder 放到动作边界，在 paired replay 中将确认违规降低 70 个百分点以上。

边界。 这是作者构造的模拟服务与攻击分布，不代表真实生产频率；宏平均 ASR 不能脱离模型、harness、evidence view、judge 与有效 rollout 分母比较。动作前 reminder 是诊断性干预，可能受 benchmark 结构与 evaluation awareness 影响，也没有证明对所有工具类型都保持效用。

推断。 AI Native 自动化的完成条件应由可重放的 state receipt 决定：文件是否真的写入、构建产物是否存在、远端 SHA 是否变化、网页是否返回正确内容。Agent 文本中的“已完成”“不会执行”只能算轨迹证据，不能单独建立事实。对提交、推送、发信、付款等不可逆动作，权限与策略检查应在 tool commit 前重新绑定到具体参数，而不是只在任务开始时提醒一次。

手术机器人与远程手术 ​

1. Surgical WAM：让手术视频先学“世界怎样变化”，再学动作 ​

事实。 Surgical WAM 基于 Cosmos Policy，用同一 diffusion transformer 联合生成未来内镜画面与 dVRK action chunk。训练分两阶段：先在不含运动学标签的视频上只优化未来视频；再用固定动作示教预算联合微调视频和动作。部署时一次预测 16 步，只执行前 4 步，再从新观察重规划；动作 token 在扩散过程中持续读取未来预测 token。论文原文｜HTML 全文

作者结果。 实验使用 SurRoL 的 Needle Pick、Peg Transfer、Needle Regrasp 和 BiPeg Transfer 四个模拟任务，训练集为 10,000 条带动作示教，每个结果评估 100 个 episode。在完全相同的 backbone、动作标签、采样器和评估协议下，额外视频预训练把平均成功率从 63.5% 提到 77.8%，Peg Transfer 从 66% 提到 86%。预训练模型 80k 步达到 86% 峰值，无预训练模型需 160k 步达到 79%；继续微调到 120k/160k 后，预训练模型反而降到 34%/56.5%，作者归因为有限示教侵蚀了视觉动力学先验。

边界。 闭环执行结果全部来自模拟器，不包含组织损伤、力/RCM 约束、器械误差与网络时延。JIGSAWS 真实 dVRK 视频只报告“同样的定性趋势”，没有给出真实机器人闭环任务成功率。平均 77.8% 仍远低于医疗系统要求，且 future video 在推理时被计算后丢弃，没有被用作在线安全证据。

推断。 对 Nathan 的手术机器人 RL 路线，最现实的数据杠杆可能不是立即扩大专家遥操作量，而是先建设视频资产：阶段、器械、组织、接触事件、视角、术式和质量标签。无动作视频可训练视觉动力学；少量同步主从/关节/末端数据用于把先验接到可执行动作；力、RCM 和损伤相关数据另建硬安全层。最关键的实验不是“视频越多越好”，而是按视频来源和接触阶段测量哪类预训练真正提高闭环成功、哪类引入错误先验。

2. FACT：让失败动作监督后果，而不是污染策略 ​

事实。 传统 WAM 多用成功示教训练未来预测，测试时即使动作很差，也可能生成“成功的未来”。FACT 将 token 顺序改为 action → value/future：成功轨迹同时监督动作、进度与未来画面；失败轨迹屏蔽 action imitation loss，只保留失败后的真实画面和降低后的进度值。推理时可只生成动作，也可采样多个动作，再以动作条件下的 progress head 选出候选。论文原文｜HTML 全文｜作者项目页

作者结果。 RoboTwin 50 任务中加入约 1,300 条 rollout failure，平均成功率从无视频协同训练的 81.8% 提到 85.6%，再以失败后果训练提升到 87.5%。真实双臂五个已见任务中，单样本 FACT 为 82%，失败感知训练为 89%，四候选评分为 92%；三个未见外观/指令变体分别为 67%、77% 和 82%。若把失败动作也加入 imitation loss，真实任务成功率降到 63%。512 个留出未来样本上，失败轨迹 PSNR 从 19.51 提到 25.92，成功轨迹基本不变。

边界。 真实任务是方块、碗、递交与倾倒，不是手术；每个表格单元只有 20 次试验，候选评分用更多推理换可靠性。失败进度值基于均匀时间进度与人工 failure onset，不等同于组织风险或临床阶段价值。论文的局限部分也承认，best-of-N 会直接增加部署计算。

推断。 手术机器人数据管线应把失败拆成三种用途：失败前的正确动作可保留为示教；导致失败的动作只监督后果、风险和恢复价值；失败后的恢复动作可作为独立技能。网络抖动、丢帧、主从不一致、夹持滑脱、超力、RCM residual 和人工接管都应记录 failure_onset / attempted_action / observed_consequence / recovery / final_outcome，而不是只把整段 episode 标成 success/fail。

论文 / 产品 / 监管动态 ​

论文 ​

  • AI Native 上下文维护： “Catastrophic Remembering”把规则膨胀定位为理由/provenance 丢失，而不是简单的文件太长。
  • Agent 安全评估： REDAgentBench 把安全结果落到服务回执与最终状态，并暴露“认出规则但仍执行”的动作边界失效。
  • 手术机器人学习： Surgical WAM 证明无动作手术视频可能在固定动作预算下改善模拟闭环控制，但真实闭环证据仍缺失。
  • 机器人学习： FACT 给出失败数据的更安全用法：模仿成功动作，预测失败动作的后果。
  • 相关跟踪： VIScore 尝试用 Veracity、Influence、Sobriety 三个因子诊断 world model 是否真的支持规划；其跨任务 success correlation 超过 0.75，但仍是通用 PushT/Reacher/Two-Room 等任务，尚未验证手术场景。VIScore 论文

产品与监管 ​

最近 72 小时没有足够高价值的新手术机器人产品、远程手术临床或监管进展；本期刻意留白。

对 Nathan 当前项目的启示 ​

1. PAI / AI Native：给每条长期规则补一个最小因果头 ​

建议字段：rule_id / trigger / rationale / evidence / owner / last_reviewed / removal_test / safety_class。运行时只渲染规则正文；维护和压缩时读取完整因果头。安全与隐私规则标记为 human_delete_only。

最小实验与完成标准： 从 PAI 和仓库 Agent 指令抽取 30 条规则，逐条判断“为什么存在、什么测试能证明可删”。完成标准不是删掉多少，而是 100% 规则可追溯到来源；随机移除一条非安全规则时，相关历史失败回放与正常任务回归都通过。

2. AI 自动化：把环境回执设为唯一完成事实 ​

对写文件、构建、commit、push、部署分别定义 receipt：文件 hash、构建退出码与目标 HTML、commit SHA、远端 ref、线上页面内容。自然语言总结只引用这些 receipt，不自行建立事实。

完成标准： 任一动作出现“Agent 声称成功但 receipt 不匹配”时任务必须保持未完成；不可逆工具调用前重新核验目标、权限与参数；部署验证至少同时检查远端 SHA 和公开页面内容。

3. 手术机器人 RL：先验证“视频先验的边际价值”，再扩大遥操作采集 ​

构建三组等动作预算实验：无视频预训练、模拟视频预训练、真实内镜视频预训练。按自由运动、接触建立、牵拉/传递、精细放置分层报告 success 和 failure onset，而不是只给总成功率。

完成标准： 固定动作示教条数、模型、训练步数和执行 horizon；至少三个随机种子；同时报告峰值 checkpoint 与固定步数结果，防止像 Surgical WAM 一样用最优 checkpoint 掩盖后期退化。

4. 远程手术：把网络故障轨迹变成因果训练与验证资产 ​

将一次远程操作分为 intended_action → transmitted_action → patient_side_accepted_action → observed_effect。延迟、抖动、丢包、重传、时钟偏差和控制权切换都进入同一事件账本；不能只保存视频和最终成败。

完成标准： 每个动作能回答“操作者意图、链路实际送达、患者侧实际接受、环境实际变化”四个问题；重试不会重复执行；任何 hard safety violation 能追溯到具体输入、版本和时间窗。

5. 手术机器人失败数据：分开 imitation、consequence 与 recovery ​

不要把整段失败 episode 丢弃或直接混进行为克隆。以 failure onset 切片：失败前有效动作进入 imitation，致错动作进入 consequence/value，恢复段进入 recovery policy；无法确定 onset 的样本只用于表征或人工复核。

完成标准： 与 success-only baseline 比较时，failure-aware 模型必须同时降低高风险失败率、保持正常成功轨迹预测质量，并报告额外推理延迟；任何 value-guided candidate selection 不得绕过 RCM、力、速度和工作空间硬约束。

值得继续跟踪的问题 ​

  1. Agent 规则的 rationale 何时也会陈旧？谁来检测“注释与规则已经分叉”？
  2. PAI 的 last_reviewed 能否从时间提醒升级为可执行 removal/regression test？
  3. Recognition–Execution Gap 是模型问题、harness 问题，还是工具 API 缺少 pre-commit policy gate？
  4. Agent 安全评估怎样建立与手术机器人相同的“意图—指令—执行—环境结果”链路？
  5. Surgical WAM 在真实 dVRK、软组织与力/RCM 约束下，视频预训练的 14.3 个百分点优势还能保留多少？
  6. 哪类无动作视频提供可迁移的接触动力学，哪类只让生成画面更逼真？
  7. Surgical WAM 预训练模型继续微调后显著退化，是否需要冻结、低秩适配、分层学习率或 continual-learning 约束保护视觉先验？
  8. FACT 的 failure onset 若由人工或简单进度定义，如何扩展到组织损伤风险、器械滑脱和网络状态陈旧？
  9. 失败动作只监督后果时，共享 backbone 是否仍会间接把错误动作写回 policy？怎样用梯度隔离或因果消融验证？
  10. 世界模型的未来画面能否成为运行时 safety evidence，而不是推理后直接丢弃的辅助 token？
