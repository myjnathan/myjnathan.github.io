AI 与手术机器人晨报｜2026-08-12 ​

主题：缩短承诺，固定边界——把长期自主拆成可重评估的窗口

信息窗口：2026-08-10 至 2026-08-12（北京时间）。arXiv 于 8 月 11 日公布新批次，本期只保留四项与 AI Native、远程医疗、手术机器人和机器人学习直接相关的工作。论文均为 8 月 10 日提交的 v1 预印本；除论文作者的实验外，尚无独立复现或临床验证。FDA、Intuitive、CMR Surgical、Johnson & Johnson 等官方渠道在该窗口内没有新的手术机器人监管决定、远程手术临床里程碑或关键产品发布，因此产品/监管部分刻意缩短。

今日摘要 ​

  1. Agent 安全不应靠一次写死的 system prompt，而应靠可归因、可回滚的局部演化。 SHE 将 harness 拆成 System Prompt、Rule Bank、Safety Memory 和 Tool Policy；只有候选修改同时提高安全且不降低效用才升级。其 Agent-SafetyBench 平均攻击成功率从初始 harness 的 8.6% 降至 5.5%，攻击下效用从 33.5% 升至 47.6%。
  2. 实时医疗 AI 的突破点不是单模型更大，而是不同时间预算的 Agent 异步协作。 AMIE Video 用低延迟 Talker、深推理 Planner 和持续感知 Perception 分离“现在要回应”与“稍后要想清楚”。在 100 个模拟临床情景的随机 OSCE 中，评审将其病史采集、诊断、管理和视频观察评为与基层医生相当或更好，但医生在关系建立与合作感上仍占优。
  3. 手术机器人 action chunk 不该一次执行到底。 TDHD 对同一 flow-matching 策略施加小噪声扰动，比较两条未来轨迹的逐步分歧；绝对分歧或相对跳变超阈值就提前截断并重规划。真实双臂仿 da Vinci 平台上，组织操作端到端成功率由 55% 提升到 80%，针操作仅由 55% 提升到 60%。
  4. 机器人学习的基础设施正在从“每个模型配一套环境”转向稳定契约。 XPolicyLab 用统一 observation/action/trajectory schema 和隔离式 client/server 把 N 个策略接 M 个环境的集成成本从 O(NM) 改为 O(N+M)，已接入 42 个策略；但其真实双臂榜单最好策略成功率也只有 12.8%，标准化让差距可测量，并没有消除 sim-to-real。
  5. 交叉结论：高风险自主系统的可靠性来自两件事——固定接口边界，缩短不可逆承诺。 SHE 限制一次修改能动哪些安全部件；AMIE 限制不同 Agent 的时间预算与职责；TDHD 限制一次开放环执行多远；XPolicyLab 限制策略与环境如何交换状态。四者都没有要求一个模块“一次做对全部事情”。

AI 前沿 ​

1. SHE：让 Agent harness 从失败轨迹中做有边界的局部演化 ​

事实。 SHE 将 Agent harness 表示为四个可编辑但职责分离的对象：System Prompt 定义全局行为契约，Rule Bank 表达风险条件与干预，Safety Memory 保存反复无法修复的失败经验，Tool Policy 约束工具权限与运行时执行。一次 rollout 失败后，系统先做风险诊断和责任路由，只修改被归因的 artifact；候选修改要经过 schema/有效性检查，并且只有在安全指标提高、正常任务效用不下降时才成为新版本，否则恢复上一 best harness。论文原文｜HTML 全文｜作者代码

作者结果。 论文从 Agent-SafetyBench 官方 2,000 个任务中取前 200 个，15 个用于 20 轮 evolution，185 个只用于最终评估；每个任务包含 clean 与 context poisoning、indirect injection、tool tampering、memory injection、composite attack 五类攻击条件。相较初始解耦 harness，演化后平均攻击成功率从 8.6% 降至 5.5%，clean unsafe behavior rate 从 25.7% 降至 19.8%，攻击下效用从 33.5% 升至 47.6%。在完全留出的 AgentHarm 上，Harm Score 从 19.8% 降至 9.8%，拒绝有害任务从 78.4% 升至 86.4%。

边界。 evolution 只使用 15 个任务、两次 rollout 重复，核心 judge 与演化模型仍是 LLM；论文用温度 0 降低随机性，却不能消除评审模型偏差。安全与效用由固定 benchmark 协议定义，候选修改可能学到评估器而非真实风险。它证明了“局部、受门控的 harness 更新”比静态规则更有潜力，不证明 harness 可以无人监管地自我修改。

推断。 对 AI Native 系统，安全修复应落到明确 owner，而不是把所有失败都追加进一个长 prompt。最小对象可拆成 behavior contract / task rules / incident memory / tool authority，每次修改都附触发轨迹、目标 artifact、回归集、效用差异和 rollback id。权限与数据外发边界不能由同一个负责提高任务成功率的 judge 单独批准。

2. AMIE Video：低延迟对话、深推理与持续感知采用不同时间尺度 ​

事实。 Google Research 与 Google DeepMind 的 AMIE Video 基于 Gemini 3 Flash / 3.1 Pro，由三个异步 Agent 组成。Talker 只看最近 5 秒视频，以较小计算预算负责自然打断和低延迟回应；Planner 维护症状摘要、鉴别诊断、管理计划和对话目标，深推理最多每 10 秒触发一次；Perception 处理更长的音视频窗口并持久记录咳嗽、姿态、语速等临床线索。Talker 始终读取另两个 Agent 的最新状态，而不等待它们完成。论文原文｜HTML 全文

作者结果。 主研究包含 100 个带音视频线索和引导式查体的模拟情景、15 名专业 patient actors、10 名实际问诊的美国基层医生和 20 名独立临床评审；论文摘要把两组医生合计为 30 名。临床评审认为 AMIE Video 在病史采集、诊断、管理、身体观察与检查上与医生相当或更好。Patient actors 更偏好 AMIE 的评估与解释方式，但在 rapport 和 partnership building 上更偏好医生；视频版相对文字版在沟通有效性、便利性和“被理解感”上更受偏好。

边界。 这是 OSCE 模拟问诊，不是真实患者或前瞻临床试验；研究由系统开发方完成。论文明确指出模型对精细解剖位置、细微情绪和高频运动仍不稳定。异步架构还引入新的状态陈旧风险：Talker 可能在 Planner 或 Perception 更新完成前回应。作者用高层目标、提示和持续处理减轻错位，但没有证明这一风险在真实急症中可接受。

推断。 对远程医疗或远程手术辅助，关键不是把视频、语音、术式知识和对话全部塞给一个实时模型，而是把 fast path 与 slow path 分开：fast path 只做低延迟交互和硬安全动作，slow path 做阶段推理、风险累积和复盘；所有输出都带 source_timestamp / state_version / freshness_budget。慢 Agent 的新结论不能静默覆盖已经执行的实时决策，应触发显式协调或升级。

手术机器人与远程手术 ​

1. TDHD：用轨迹分歧决定 action chunk 还能安全执行多远 ​

事实。 TDHD 面向生成 action chunk 的 flow-matching VLA。每次推理从初始噪声 z1 生成主轨迹，再用很小扰动 z2 = z1 + εη 生成第二条轨迹；逐步计算两条动作的 L2 分歧。若分歧超过绝对阈值，或相邻步骤的分歧比例突然跳变，就把执行长度截断到当前可靠区间，重新读取视觉状态并规划下一 chunk。视觉语言 encoder 每轮只运行一次，额外成本主要来自较小 action decoder 的第二次生成。论文原文｜HTML 全文

作者结果。 团队在双 RM65-B 机械臂上安装 dVRK 风格末端器械，用外部 RGB-D 与双腕 RGB 相机、双 Geomagic Touch 采集 600 条 30 Hz 遥操作示教：针的 reach/pick/regrasp 和仿组织的 reach/lift/resection 各 100 条。五种方法、六个子任务、每项 20 次，共 600 次真实机器人试验。π0.5 + TDHD 的针操作端到端成功率为 60%，基线 π0.5 为 55%；组织操作为 80% 对 55%。10 次重复的消融中，TDHD 相对最佳固定 horizon 把 needle pick 从 80% 提到 90%、tissue resection 从 60% 提到 70%，但 needle regrasp 均为 50%。

边界。 数据来自可重复软体 phantom，而非离体/在体组织；每个端到端比例只有 20 次试验，5 个百分点等于 1 次成功差异。轨迹对噪声敏感只是模型不稳定性的 proxy，不是碰撞、组织损伤或控制安全的证明；绝对/相对阈值仍需人工校准。它能决定“何时重规划”，不能替代 RCM、速度、力和工作空间硬约束。

推断。 远程手术的自主或辅助动作应把 action horizon 变成运行时变量，而不是模型固定超参数。除策略轨迹分歧外，还应同时纳入网络数据年龄、图像冻结、力/RCM residual 和操作者接管信号；任何硬约束触发都直接进入 hold，而不是仅缩短 chunk。价值最大的测量不是平均成功率，而是“高风险接触阶段比稳定自由运动阶段缩短了多少、是否在损伤前触发”。

2. XPolicyLab：标准化策略—环境边界，也把 sim-to-real 落差暴露出来 ​

事实。 XPolicyLab 定义统一 observation、action 与 trajectory schema，以及 update_obs / get_action / batch / reset 最小适配器。策略推理与仿真/机器人控制运行在依赖隔离的 client/server 中，可在同机或远端 GPU；请求有唯一 ID，断线重试返回缓存结果而不重复推进有状态策略，server instance 变化则终止当前 trial。项目截至 8 月 8 日接入 42 个 VLA、WAM、diffusion、memory 与 imitation policy，并连接 RoboTwin、RoboDojo 仿真和真实机器人评测。论文原文｜HTML 全文｜项目页｜代码仓库

作者结果。 六名不熟悉 XPolicyLab 的工程师以交叉顺序完成 π0.5 → RoboDojo 集成：从上游仓库手写中位耗时超过 5 小时，按标准手工接入约 2 小时，用固定 Cursor + Opus 5 和仓库内 agent skills 后约 30 分钟。更重要的是统一评测暴露了泛化缺口：RoboTwin clean 榜首 FastWAM 为 77.8%，随机化后仅 1.9%；真实双臂 18 任务榜首 π0.5 成功率也只有 12.8%，且真实排名只部分跟随仿真。

边界。 集成效率实验只有 6 人、一个策略和一个目标环境，并且参与者在三种条件间可能形成熟悉效应；Agent 条件把人工编写代码计为约 0 行，不代表没有人工配置、运行、审查与调试。统一 schema 只能减少接口与依赖噪声，无法标准化真实场景重置、硬件磨损、传感同步和安全监督。

推断。 对手术机器人 RL 平台，应先建立稳定的 policy contract，再比较算法：观测字段、相机/坐标系、动作单位、chunk 长度、状态 reset、deadline、幂等重试与 server 重启语义都必须版本化。策略服务器可以远端化，但患者侧硬实时控制、限幅、RCM、急停和最后授权必须留在环境/机器人侧；网络重试绝不能让同一个逻辑动作执行两次。

论文 / 产品 / 监管动态 ​

论文 ​

  • AI Native 安全： SHE 把 harness 更新从“重写大 prompt”变成有责任边界、回归门和回滚状态的局部修改。
  • 实时医疗 AI： AMIE Video 用异步多 Agent 解决低延迟交互、深临床推理与持续音视频感知的时间预算冲突。
  • 手术机器人学习： TDHD 直接把 action chunk 的开放环长度变成由模型轨迹稳定性决定的运行时量。
  • 机器人学习基础设施： XPolicyLab 统一策略与环境契约，并用同一接口同时暴露 clean/randomized、sim/real 的真实差距。

产品与监管 ​

最近 72 小时没有足以扩写的手术机器人产品、远程手术临床或监管新进展；本期不以旧闻填充。

对 Nathan 当前项目的启示 ​

1. AI Native：把 harness 变成四类独立版本对象 ​

将行为契约、任务规则、失败记忆和工具权限分开存储；每次候选修改只触碰被归因的对象，并保存失败轨迹、评审指标、版本与 rollback。

最小实验与完成标准： 从近期自动化/编码任务选 20 条历史轨迹，人工标注失败属于 context、rule、memory 还是 authority。候选修复必须通过原失败重放、10 条正常任务回归和 5 条相邻攻击；安全提升且任务效用不退化才升级，任何版本可一条命令回退。

2. 远程手术：建立 fast / slow / hard 三条控制路径 ​

  • fast path：低延迟遥操作、视频/网络状态和局部保护反射。
  • slow path：阶段推理、风险聚合、策略建议与事件复盘。
  • hard path：RCM、力/速度限幅、工作空间、急停和患者侧最终授权，不接受生成式更新。

完成标准： 所有跨路径消息带单调时间戳、状态版本和 freshness budget；slow path 超时不阻塞 fast path；fast/slow 结论冲突进入明确仲裁状态；hard path 在任何模型或网络失效时仍独立有效。

3. 手术机器人 VLA：让 action horizon 随阶段和证据变化 ​

离体或 phantom 回放中，对自由运动、接触建立、牵拉、切割、器械交接分别统计轨迹分歧、物理 residual 与最佳重规划点，不用一个固定 chunk 覆盖全程。

完成标准： 动态 horizon 在不增加硬约束违规的前提下优于所有固定 horizon；报告 95/99 分位的触发延迟、重规划频率、最短/最长 chunk、阶段条件成功率与误触发，而不只报告平均成功率。

4. 机器人 RL：先统一 policy contract，再比较模型 ​

定义最小 schema：多相机命名与标定、关节/末端坐标系、夹爪单位、动作时间戳、chunk、reset、deadline、幂等 request id、model/server instance id 和安全 envelope。

完成标准： 同一个策略 adapter 可在仿真、台架和真实机器人复用；相机通道、单位或坐标系错配在动作下发前被 conformance test 拦截；策略进程重启会终止 episode，断线重试不会重复执行动作。

5. 远程医疗/手术视频 AI：把“看见”与“说出”分开审计 ​

AMIE 的 Perception/Planner/Talker 分层可迁移为术中观察、风险推理和人机交互三个服务，但术中系统需要比问诊更严格的状态一致性。

完成标准： 对咳嗽式瞬时事件、持续组织牵拉、器械遮挡、视频冻结和高频运动分别测试 detection-to-advice 延迟；任何建议能追溯到具体帧窗口、感知版本和推理版本；陈旧状态不得以当前事实呈现。

值得继续跟踪的问题 ​

  1. SHE 的安全—效用 judge 若本身被 prompt injection 或 benchmark bias 影响，谁来批准 harness 更新？
  2. 哪些安全规则必须永久只读，不能进入 Agent 自动 evolution？
  3. AMIE 的 Talker 在 Planner/Perception 尚未更新时会怎样表达不确定性，能否避免把陈旧状态说成最新结论？
  4. 实时医疗多 Agent 的跨模块状态需要强一致、因果一致，还是带 freshness budget 的最终一致？
  5. TDHD 的两轨迹分歧能否预测真实接触风险，还是只是在检测 flow-matching decoder 对噪声的敏感性？
  6. 动态 horizon 与网络 jitter、视频帧率下降、力 residual 联合时，应采用规则仲裁、风险上界还是学习式融合？
  7. π0.5 + TDHD 的针任务只多成功 1/20 次；扩大样本、换器械/组织/相机后效果是否仍成立？
  8. XPolicyLab 的统一 schema 如何表达 RCM、器械轴约束、主从缩放与控制权等手术特有语义？
  9. 策略推理远端化时，request id、动作序号、数据年龄和患者侧执行确认怎样组成 exactly-once/at-most-once 契约？
  10. 同一策略在 clean 仿真、随机化仿真和真实平台的失败能否映射为统一 failure taxonomy，直接驱动下一轮数据采集？
