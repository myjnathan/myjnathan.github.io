AI 与手术机器人晨报｜2026-08-05 ​

主题：预测不是控制——把 AI / 机器人闭环建立在证据、时序与反馈上

信息窗口：2026-08-03 至 2026-08-05（北京时间）。本期主要筛选 arXiv 8 月 4 日公开批次中、对 AI Native、机器人学习和远程手术系统设计有直接工程价值的工作。近 72 小时未检索到可由医院、监管机构或论文原文核验的新远程手术临床里程碑，也没有新的高价值手术机器人监管决定，因此不重复更早的产品新闻。以下论文均为预印本，作者结果尚待同行评议、独立复现和医疗场景验证。

今日摘要 ​

  1. Agent 的改进对象正在从模型权重扩展到可执行 runtime harness。 Harness-R1 不让大模型凭“看起来合理”修改提示与工具逻辑，而是安装补丁、重跑原任务，用真实结果训练专门的 harness engineer；作者报告冻结的 Qwen3.5-9B 平均成功率由 44.3% 提升到 53.6%。但其奖励仍来自挖掘失败的同批任务，尚未充分约束未见任务回归和运行成本。
  2. 搜索何时停止，应该看证据覆盖，而不是模型是否自信。 HALT 把多跳问题拆为待证明的 hop claims，只有累计证据逐项覆盖后才停止。它在受控检索池中减少 20%–45% 的循环，但验证器本身消耗的原始 token 反而高于节省量；这是“控制信号更可靠”的证据，不是已经实现系统成本下降。
  3. 世界模型的未来预测只能产生候选，不能自动获得执行权。 CoWAM 以同步、双臂角色和碰撞收敛契约决定保留、替换或放弃动作；八个双臂仿真任务中，相对最强选择基线的闭环成功率提高 9.6 个百分点，破坏性介入低于 1%。这仍是仿真选择器结果，不是手术安全证明。
  4. 实时执行的首要条件是时间基准正确，而非事后把动作“抹平”。 一项 10 Hz 双臂 WAM 实验发现，观测、推理和已执行命令若没有准确对齐，动作 blending 无法消除 chunk 边界断裂；而环境突变时，强制沿用旧 chunk 前缀又会阻碍及时避险。
  5. 触觉预测最有价值的形态不是一次性 forecast，而是持续更新的控制状态。 ReTouch 在每个 action chunk 内用最新触觉同时修正未来触觉和动作；七个实物接触任务中，标准/挑战条件平均得分相对最强基线提高 18.4/23.8 个百分点。它的消融显示，一步延迟或固定预测都会明显损失收益。
  6. “安全范围”需要写清概率、扰动分布和统计单位。 Reachable-Action Verification 在冻结视觉编码器后，对低维接口做集合传播，并以 200 个校准初始状态构造相机位姿扰动下的 conformal action radius；99% 名义覆盖下，作者报告半径中位数收紧 2.09 倍，但这只是给定采样分布下的有限样本边际覆盖，不是任意相机故障的确定性保证。

AI 前沿 ​

1. Harness-R1：让失败轨迹修改运行时，而不只修改模型 ​

事实。 Harness-R1 把 Agent harness 定义为负责构造上下文、调解工具、验证动作和恢复执行的可执行层。专门的 9B harness engineer 从目标 Agent 的失败轨迹生成补丁；每个补丁必须可解析、可安装，并在冻结目标 Agent 上重跑同一批任务，实际结果才进入 GRPO 奖励。无效、空操作或未完成评估的补丁奖励为零。论文原文｜HTML 全文

作者结果。 在 WebShop、ALFWorld 和 DBBench 上，默认 Qwen3.5-9B 的等权平均成功率为 44.3%，Harness-R1 后为 53.6%；目标 Agent 先直接微调到 59.2% 后，为该目标重新训练的 engineer 又提升到 64.2%。对 20 个训练时未见的目标配置，目标级平均增益均为正；在 1,270 个 held-out tasks 上，三次匹配实验的成功率增益为 8.9 ± 1.5 个百分点。

来源观点与边界。 作者认为，补丁是否“合理”不能替代补丁安装后的任务结果；固定 Self-Refine 在三项基准上平均反而下降 2.6 个百分点。更关键的限制是，Harness-R1 的奖励来自同批失败任务，尚未把未见任务回归和推理成本纳入目标；论文也只研究了一轮从原始目标到微调目标的适配，没有证明多轮自我演化会收敛。

推断。 对 AI Native 工作流，更直接的实验不是训练一个 9B engineer，而是建立“小型 harness 变更闭环”：每次从失败日志生成 prompt / context routing / tool guard / recovery 候选补丁，必须在冻结任务集、回归集和成本预算上重放；只有同时满足成功率、零越权回归和时延上限的补丁，才能进入下一版自动化。

2. HALT：搜索完成的定义是“证据齐了”，不是“模型觉得够了” ​

事实。 HALT 保持原搜索 Agent、检索器和回答生成器不变，只改变停止谓词。它先从问题生成预期 hop claims；每轮检索后，小型 verifier 将累计证据对每条 claim 标为 match、partial 或 null，只有全部 match 才停止。作者在 HotpotQA、2Wiki 和 MuSiQue 的受控 BM25 检索池中评估 3B/7B Self-Ask Agent。论文原文｜HTML 全文

作者结果。 在使用 gold claims 的 3B 诊断设置中，平均循环数减少 20%–45%；但 HotpotQA 的 exact match 下降 0.9 个百分点，95% 置信区间越过预设的非劣界，因此不能把三项都写成“无损”。使用问题自动生成 claims 时，节省更小；开放语料检索发生分布变化后，HALT 在 HotpotQA 的触发率由 68.7% 降到 6.4%，在 Bamboogle 完全 abstain。

反直觉边界。 附录的校正 token 核算显示，验证器在所有实验臂上增加的原始 token 都多于少检索所节省的 token。HALT 证明的是“逐项证据覆盖可以成为更审慎的停止信号”，不是已经证明更省算力或更低成本。其主结论还依赖闭合候选池、清晰 hop 边界和 3B–7B 开源权重模型。

交叉核验与推断。 Harness-R1 用真实重跑结果筛补丁，HALT 用逐项证据覆盖决定停止，两组独立实验都反对以输出流畅度或模型自信替代外部核验。对晨报、技术调研和设计文档，可把完成条件写成显式 claim ledger：每个重要结论必须关联原始来源、反例检查和边界；检索只有在高优先级 claims 全部有证据或被明确标记“当前无证据”时结束。

手术机器人与远程手术 ​

1. CoWAM：预测未来并不赋予替换动作的权力 ​

事实。 CoWAM 接收冻结 WAM 给出的“动作 chunk + 预测未来”候选池，不重新生成动作。选择器为当前事件激活同步、角色兼容和碰撞收敛等 typed contracts；候选必须通过所有活跃义务、低风险边界和校准介入门，才可替换 nominal action。若 nominal action 也不可接受，则进入预定义 abstention fallback。论文原文｜HTML 全文

作者结果。 八个 RoboTwin 2.0 双臂仿真任务中，CoWAM 在 240 个自然闭环 episode 取得 151 次成功，最强 selective baseline 为 128 次，即提高 9.6 个百分点；180 个 matched negatives 中有五次错误介入、一次破坏性介入。选择器单次决策 88 ms、峰值 GPU 内存 4.8 GB（RTX 5880 Ada）。

边界。 契约字段、verifier 和校准都依赖任务定义；仿真 RGB-D、proprioception 与 outcome oracle 不能直接映射到真实组织、器械力学或临床后果。低于 1% 的破坏性介入在医疗场景仍可能完全不可接受。

推断。 手术机器人自主功能应把世界模型放在“proposal plane”，而非“control authority”。进针、夹持或相机调整的候选动作只有在器械角色、RCM、力/位姿上界、组织区域、操作者授权和网络状态契约全部满足时才可介入；任何一个活跃硬约束都不能被更高的任务得分抵消。

2. WAM 实时部署：先解决时间对齐，再谈平滑 ​

事实。 “World Action Models in Real Time”在 10 Hz 双臂机器人上比较同步执行、纯异步切换、事后 blending、去噪期 blending、速度引导和 prefix-conditioned generation。模型生成 24 帧 chunk，实测端到端推理延迟的中位数被设为 8 帧，并以重叠推理隐藏等待。论文原文｜HTML 全文

作者结果与观点。 未准确对齐观测、预测和已执行命令时，chunk 边界的持续不连续无法靠 blending 修复。对齐后，直接权重混合是低精度任务的可用基线，但精细操作精度下降；训练时学习前缀连续性的方案在三类任务上取得最佳综合权衡。

关键边界。 所有方法都默认旧 chunk 仍是有用引导。论文明确展示：若障碍突然出现，下一 chunk 本应大幅偏离旧轨迹，此时 prefix constraint 会从“平滑器”变成“反应阻力”。

交叉核验与远程手术推断。 CoWAM 说明“候选替换需要语义与风险契约”，本研究说明“动作拼接还需要正确的时间契约”。远程手术不能只按平均网络时延设置固定 overlap；至少应使用单调时间戳、当前执行索引、推理起始观测时刻和实际下发序号对齐，并在抖动突增、画面/状态突变或接触事件发生时解除旧前缀约束，切入快速重规划或安全停机。

3. ReTouch：把触觉 forecast 变成执行中的状态估计 ​

事实。 ReTouch 用 Tactile-Patch Encoder 保留五指身份和局部接触拓扑；高频模块在每个 action chunk 内读取最新触觉，同时修正未来触觉 latent 和动作。XHT-Dataset 含七个真实接触任务的 900 条成功演示；各方法每个任务进行 20 次实物试验。论文原文｜HTML 全文

作者结果。 相对最强基线，ReTouch 在标准和挑战条件下的平均任务得分分别提高 18.4 和 23.8 个百分点。完整模型平均得分 83.6%；固定初始触觉预测但继续更新动作时为 68.4%，并行非阻塞更新因约晚一个 action step 生效而降到 75.8%，移除结构化触觉编码后为 69.1%。

边界。 数据集只有一个 XHand–UR7e 平台、七类任务和成功演示；论文没有覆盖柔性组织、传感器灭菌封装、漂移、血液/液体污染或跨器械迁移。其“success rate”还包含多条件任务的加权部分得分，不能等同于临床成功率。

推断。 触觉闭环应尽可能驻留在机器人端或边缘实时层，而不是等待云端往返。对于组织抓取，可把“预测接触状态—实测触觉残差—动作修正”作为高频局部闭环，远端操作者/上层 AI 只下发目标和约束；评估时必须单独注入触觉延迟、漂移、丢帧和局部失效。

4. 概率可达动作验证：把相机扰动变成可报告的动作半径 ​

事实。 Probabilistic Reachable-Action Verification 冻结大视觉编码器，只在低维视觉—策略接口传播 zonotope；接口集合由 held-out 相机位姿扰动校准。评估时，从预先规定的六维相机外参扰动分布抽样，并对 rollout 级最大动作偏差做 split conformal calibration。论文原文｜HTML 全文

作者结果。 在 200 个校准 initializations 和 100 个 held-out initializations 上，99% 名义覆盖时，集合训练相对仅行为微调的 reachable-action radius 中位数收紧 2.09 倍，实测覆盖为 0.99–1.00；三次随机种子下仍保持 clean 和扰动条件至少 0.85 的闭环成功标准。

来源观点与边界。 作者明确说，只有建立从相机 pose set 到 interface set 的确定映射，才可能把当前概率半径推进到端到端保证。现有结论是对给定、可交换的扰动采样分布做有限样本边际覆盖；超出分布的内镜松动、镜头污染、遮挡和标定突变不受保证。

推断。 这为手术视觉鲁棒性提供了比“加噪后成功率”更可审计的指标：按内镜位姿/标定扰动区间报告动作偏差半径，并同时给出覆盖水平、校准样本数、统计单位和失败分布。它适合成为风险证据的一层，但必须外接 OOD/污染检测和确定性运动边界。

5. 远程手术临床进展：本窗口宁缺毋滥 ​

FDA 8 月 3–4 日发布的近期严重医疗器械召回/早期预警涉及骨内针和 convenience kits，并非手术机器人；CMR Surgical 的官方新闻列表最新手术机器人公告仍为 7 月 22 日。检索中也未发现近 72 小时可由医院公告或论文原文确认的新远程手术实施。因此本期不把 6 月在线发表、8 月见刊的 13 例混合网络远程泌尿外科单中心研究，或 7 月 22 日 OTTAVA 授权重新包装为“今日进展”。FDA 近期医疗器械召回与早期预警｜CMR Surgical 官方新闻列表

论文 / 产品 / 监管动态 ​

论文 ​

  • Agent runtime： Harness-R1 把失败条件下的 harness 编辑变成结果驱动的学习问题；HALT 把检索停止条件从生成器置信度改成逐跳证据覆盖。
  • 机器人世界模型： CoWAM 把预测未来限制在候选层，用 typed contracts 决定是否介入；异步 WAM 实验则把时间对齐确认为 chunk 平滑的前置条件。
  • 接触闭环： ReTouch 以执行期触觉持续修正未来状态和动作，消融表明“及时更新”比一次性触觉预测更关键。
  • 鲁棒性证据： Reachable-Action Verification 用集合训练与 conformal calibration 把规定相机扰动转成带覆盖水平的动作偏差半径。

产品与监管 ​

截至本期检索时间，FDA 近期严重召回/早期预警列表没有新增手术机器人条目，所核验的主要厂商官方新闻页也没有时间窗口内具备新增技术或监管证据的公告。本期因此不扩写产品动态。

对 Nathan 当前项目的启示 ​

1. 远程手术：建立跨层“时间—证据—权限”三联契约 ​

为一个实际控制动作记录：observation_monotonic_ts / inference_start_ts / current_execution_index / command_seq / network_age / active_safety_contracts / operator_authorization / fallback。动作发出前同时检查时间对齐、证据新鲜度和权限；任一项失效都不得依靠 blending 或模型置信度掩盖。

最小实验与完成标准： 注入固定时延、抖动、乱序、状态突变和接触事件五类条件；报告 P50/P95/P99 对齐误差、chunk 边界 jerk、误介入率、解除旧前缀所需时间和安全停机时间。状态突变时必须在一个控制周期内撤销旧前缀约束，乱序命令不得执行。

2. 机器人强化学习：把世界模型限制在候选生成器 ​

选择一个双臂或器械—相机协同任务，固定策略与候选池，单独评估 selector：preserve / override / abstain。契约至少包括 RCM、器械—组织区域、力/位姿上界、角色一致性和动作时序；硬约束不可被 utility 抵消。

完成标准： 除任务成功率外，强制报告 opportunity、正确介入、错误介入、破坏性介入、abstain 和 oracle headroom。先把破坏性介入的置信上界压到可接受阈值，再讨论提升成功率。

3. 手术视觉：建立相机扰动到动作偏差的风险曲线 ​

从现有仿真中定义内镜外参、标定、压缩和轻度遮挡的预期扰动分布；按 rollout 级最大动作偏差做 90%/95%/99% conformal radius，同时保留 OOD 检测通道。

完成标准： 校准集和测试集按场景/轨迹分组隔离；每个半径同时给出样本数、覆盖率和任务成功底线。分布外污染或突变必须触发 abstain，不能拿分布内半径外推。

4. 触觉闭环：比较更新频率，而不只比较“有无触觉” ​

在一个稳定接触或夹持任务上比较：无触觉、一次性触觉预测、延迟一个 action step 更新、每步更新四组。网络侧单独注入局部计算延迟，避免把高频闭环误放到云端。

完成标准： 统一报告成功率、峰值力、滑移次数、触觉残差、修正延迟和传感失效后行为；若晚一步更新显著退化，应将该延迟写成系统级实时约束。

5. AI Native：从“改 prompt”升级为可回归的 harness 工程 ​

将 Agent 失败按 context / tool mediation / action validation / recovery 四个位置归因，生成最小补丁；每个补丁只在临时副本安装，跑冻结任务、held-out 回归和成本检查后再决定是否保留。

完成标准： 补丁必须提供失败轨迹、修改位置、重跑前后结果、未见任务回归、token/时延变化和回滚方式；禁止用“输出看起来更好”代替可执行验证。

值得继续跟踪的问题 ​

  1. Harness 自动编辑工具校验与恢复逻辑时，谁验证 verifier 本身没有被补丁削弱？
  2. 同批任务奖励导致的 harness 过拟合，能否用影子流量、冻结安全集和最坏任务回归共同约束？
  3. HALT 的逐项证据 verifier 如何在增加 token 的同时真正降低端到端成本？能否改成缓存、批量或轻量判别器？
  4. 手术任务中的 coordination contracts 应由风险分析、临床工作流还是数据学习产生？哪些字段必须是确定性规则？
  5. 远程链路时延分布变化时，WAM 的 d_est 应如何在线更新，且不引入新的动作切换竞态？
  6. 环境突变与传感噪声如何区分？何时解除 prefix constraint，何时保持平滑，何时直接停机？
  7. 触觉预测在软组织上如何表示不可逆损伤风险，而不仅是下一时刻接触状态？
  8. Conformal action radius 在患者、器械和内镜域同时变化时是否仍有覆盖意义？应该按何种临床单元做 exchangeability 分组？
  9. 如何把“候选生成—契约选择—高频触觉修正—确定性安全层—人工接管”串成可独立验证的五层架构？
