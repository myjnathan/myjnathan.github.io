AI 与手术机器人晨报｜2026-08-07 ​

主题：预算是闭环的一部分——让 Agent、感知与动作知道何时继续、何时够了

信息窗口：2026-08-04 至 2026-08-07（北京时间）。本期筛选 arXiv 8 月 5–6 日公开批次中，对 AI Native、机器人学习和远程手术工程有直接价值的工作。近 72 小时未检索到可由医院、监管机构或厂商原始公告核验的新远程手术临床里程碑或手术机器人监管决定，因此产品/监管部分从简，不重复更早新闻。以下论文均为预印本；作者结果尚待同行评议、独立复现和医疗场景验证。

今日摘要 ​

  1. 长时程 Agent 的关键不是无限延长一次对话，而是把任务切成有限 mission，同时让证据、约束、失败路线和审查结论持久化。 Argus 用 Manager / Planner / Engineer / Reviewer 分权，并把用户稳定意图与可修订的操作目标分开；作者报告 SWE-Bench Pro 约 78%，Direct Copilot 为 59%，但使用了 1.41 倍总 token，且所谓 runtime 自演化主要是纵向观察，不是受控消融。
  2. “长上下文”是否有用，取决于上下文里有没有真实依赖关系。 OctoLong 用 AST、语言服务器和包管理器递归追踪跨仓库代码引用；作者称只用依赖富集数据替换 12% 的传统长上下文训练语料，就能改善检索、状态跟踪和仓库级理解。它支持的是“结构化上下文工程”，不是把更多文件塞进 prompt。
  3. 手术视觉的实时性首先是传感方案问题，其次才是网络问题。 一项单帧结构光腹腔镜方案用 LED + 被动二值掩模替代 DMD 和投影—相机同步，在 722 对 phantom 数据上取得 3.70 mm MAE，并在 A100 上达到 26 Hz；但计时排除了数据加载、显示和 I/O，也未覆盖血液、高光和组织变形。
  4. 扩散策略的去噪步数不应是固定超参数。 POGP 为每个中间去噪前缀学习价值函数，在四个 MuJoCo 环境中平均减少约 2.7 倍去噪迭代，并保留接近完整链的性能；但尚未在真实机器人、长扩散链或精细操作上验证。
  5. 边缘部署要先测系统瓶颈，再决定是否量化模型。 8GB Jetson 双臂实验中，零拷贝没有解决内存或丢帧问题，却释放了 CPU 和尾延迟；FP16 把 ACT 平均推理从 114.02 ms 降到 17.93 ms，但最终 10 Hz 控制率仍被 USB 相机限制。对远程手术而言，“最快模型”不等于“最快闭环”。
  6. 交叉结论：预算分配本身应成为可观测、可验证的控制策略。 Argus 与 OctoLong 分别从 runtime 和训练数据证明“保留什么”比“保留多少”更重要；POGP 与 Jetson 实验分别从算法和系统证明“算多久”必须由动作难度与真实瓶颈决定。这个趋势比单一 benchmark 提升更值得 Nathan 跟踪。

AI 前沿 ​

1. Argus：把长任务变成“有限 mission + 持久证据”，而不是一条无限 transcript ​

事实。 Argus 把稳定用户意图、当前操作目标、已知约束和验证标准写成可演化工作契约。Manager 控制目标与阶段，Planner 选择工作单元，Engineer 执行，Reviewer 在需要时独立决定是否完成；每个 mission 必须明确完成、暂停或移交，连续性由持久项目状态承担。记忆、技能、验证器、路由选择和被否决路线只有通过角色所有者审查与任务原生验证后，才进入后续 mission。论文原文｜HTML 全文

作者结果。 论文报告 Argus 在 SWE-Bench Pro 上约为 78%，Direct Copilot 为 59%，总 token 为后者的 1.41 倍；731 个任务中，Reviewer 拒绝结束 43 次，其中 34 次后来通过官方验证器，22 次完成严格审查闭环。成熟 wave 相比启动 wave 的 solve-input token 少 21%，每任务活跃工作时间少 15%。

来源观点与边界。 作者的核心主张是：允许 Agent 修订操作目标时，必须用证据、权限和记录把“合理转向”与“失败后的自我合理化”区分开。论文也明确承认，runtime 自演化的纵向结果是观察性证据，不是受控学习消融；公开 trace 没有测量零人工干预率，验证强度仍受证据边界和 verifier 质量限制。

推断。 对 Nathan 的 AI Native 工作流，最值得复用的不是四个角色名称，而是三条不变量：standing intent 不能被 Agent 偷换；目标/约束的实质变化必须有证据和授权；被证明无效的路线也应保留为后续决策证据。自动化记忆不应只记“上次做了什么”，还要记“哪些路线被否决、为什么不能重试”。

2. OctoLong：长上下文训练的单位应该是依赖图，不是文件拼盘 ​

事实。 OctoLong 用 AST parser、语言服务器和包管理器递归追踪代码引用，构造可达数百万 token、含跨仓库依赖的代码上下文。团队在 600M–14B 参数基础模型上做 context-extension mid-training；训练混合物约 500 亿 token，其中约 62 亿来自 OctoLong 上下文，随后再做约 100 亿 token 指令微调。论文原文

作者结果。 作者称，在与 18 个开放权重长上下文模型比较时，只用 OctoLong 数据替换传统 context-extension 语料的 12%，就能改善长距离检索、长期状态跟踪、仓库级代码理解和下游 Agent 任务，也提升短上下文 API 使用能力。

来源观点与边界。 论文支持的是“依赖密度提高了训练信号”，不等于任意项目只要完整索引 AST 就能得到同样收益。其摘要没有给出所有任务的绝对分数、推理成本和跨语言失效模式；结论还依赖专门的中期训练，而不是一个可直接安装的检索技巧。

交叉核验与推断。 Argus 从运行时侧说明，长任务需要 reviewed compression 与显式状态；OctoLong 从训练数据侧说明，长上下文需要真实引用路径。两项工作独立指向同一原则：AI Native 系统的上下文路由应优先恢复“当前目标 → 相关决策 → 依赖对象 → 验证证据”的图，而不是按目录批量加载。对唯精云或远程手术代码库，可先建立最小 dependency-aware context pack，再评估是否真的减少重复搜索和错误修改。

手术机器人与远程手术 ​

1. 单帧结构光腹腔镜：用主动光学减少深度歧义，但端到端实时仍未成立 ​

事实。 该方案把 LED 照明的被动二值掩模装入双通道腹腔镜的一路，另一路采集被条纹照明的目标；VQ-VAE 把图像编码为离散 latent，U-Net depth head 直接预测深度。相比多帧 fringe projection，它不需要 DMD、投影—相机同步和独立 mask branch。论文原文｜HTML 全文

作者结果。 在 722 对 SSLE–Zivid phantom 图像的固定训练/验证/测试划分上，作者报告 MAE 3.70 mm、AbsRel 0.0326、δ=1.1 准确率 0.962；在 A100 上连续 301 帧的模型推理均值为 26.0 Hz，约 38.4 ms/帧。

关键边界。 26 Hz 只计模型推理，不含数据加载、显示和文件 I/O；参考深度还包含 SSLE–Zivid 外参标定与跨相机重投影误差。实验全部是组织 phantom，未验证镜面高光、血液、烟雾、软组织变形和在体运动，也没有在可部署边缘算力上给出端到端延迟。

推断。 这项工作的工程价值不是“AI 已解决手术深度”，而是展示主动光学 + 学习重建可以用更简单的硬件解除单目几何歧义。对远程手术，更合理的下一步是把深度模块当作可降级传感通道：测量从光子到控制输入的总时延、标定漂移和失效可检测性；一旦图案置信度或标定一致性下降，系统应退回普通双目/单目与人工控制，而不是输出看似连续的错误深度。

2. POGP：把“还要不要继续去噪”变成策略的一部分 ​

事实。 Prefix-Optimal Generative Policies 为扩散链每个中间前缀学习 prefix value function。该值函数既监督中间输出尽早成为可用动作，也在测试时判断继续去噪是否仍可能带来有意义改善；若边际价值不足，策略提前停止。论文原文｜HTML 全文

作者结果。 在四个 MuJoCo 环境与 12 个 baseline 的比较中，POGP 平均将去噪迭代减少约 2.7 倍，同时保留接近完整链的性能；相对动态扩散 baseline D3P，平均性能高约 3.5%，迭代数少 18.2%。

边界。 结果只覆盖 MuJoCo，尚未覆盖视觉输入、真实机器人、接触丰富操作或 50 步以上长扩散链。价值函数错估的安全后果也没有按医疗级风险分层；“提前停止”在仿真中是算力优化，在手术动作中可能成为精度损失或异常响应延迟。

推断。 对手术机器人学习，动态计算不能只优化平均 FPS，应按动作阶段分配预算：自由空间移动可早停，接触建立、穿刺、牵拉和打结临界阶段增加推理与验证。停止条件至少同时考虑动作价值收敛、状态新鲜度、接触事件和安全层余量；任何一项不满足时，宁可降速或 abstain。

3. 8GB Jetson 双臂部署：先找到绑定约束，再谈模型压缩 ​

事实。 研究在 Jetson Orin Nano Super 8GB 上部署三相机双臂 SO-101 系统，比较常规采集与 GStreamer/NVMM 零拷贝，并把 ACT 转为 TensorRT FP16/INT8。训练在桌面 RTX 3070 上离线完成，实机任务是可变形 beanbag 的双臂 pick-and-place。论文原文｜HTML 全文

作者结果。 常规管线本来就能装入内存且没有丢帧；零拷贝真正改善的是峰值单核 CPU（98.0% → 77.0%）和最坏采集延迟（117.31 ms → 101.52 ms）。ACT 在 100k 训练步达到 19/20，Diffusion Policy 在相同数据、200k 步下为 0/10；作者谨慎归因于在给定预算下的收敛成本，而不是架构精度上限。FP16/INT8 将平均推理从 114.02 ms 降到 17.93/12.65 ms，三种精度分别为 19/20、18/20、19/20，但 10 Hz 最终仍由 USB 相机限制。

关键边界。 每种精度仅 20 次试验，一次就占 5 个百分点，不能证明精度等价；任务容错高，INT8 某一动作维度约 16.98% 的最坏偏差在精细插入中可能完全不可接受。论文没有报告每个 engine 的推理峰值显存、Diffusion Policy 推理时延和失败分类，FP32 到 FP16 的 6.4 倍改进还混合了图编译与精度效应。

交叉核验与远程手术推断。 POGP 从算法内部压缩无效去噪，Jetson 研究从系统外部发现传感总线才是绑定约束。两者共同说明：优化顺序应是 端到端关键路径测量 → 识别绑定资源 → 动态分配计算 → 再做量化/压缩。远程手术边缘节点不能只报模型推理时延；必须同时报告相机曝光/采集、编码、网络、解码、状态融合、策略、确定性安全层和驱动执行的 P50/P95/P99。

4. 远程手术临床进展：本窗口没有足够高价值的新事实 ​

截至本期检索时间，FDA CDRH 最新可见机器人手术监管里程碑仍是 7 月 21 日 OTTAVA De Novo 决定（厂商 7 月 22 日公告），不在 72 小时窗口；FDA 近期更新中未见新的手术机器人授权。主要厂商和医院原始公告中，也没有检索到本窗口内可核验的新远程手术临床实施。因此本期不把更早的 OTTAVA、Toumai 或远程手术案例重新包装成今日进展。FDA De Novo 数据库｜FDA CDRH News and Updates｜J&J OTTAVA 官方公告（2026-07-22）

论文 / 产品 / 监管动态 ​

论文 ​

  • AI runtime： Argus 把长任务建模为有界 mission 与可审查持久状态，强调目标修订的证据和权限边界。
  • AI context： OctoLong 用跨仓库依赖图构造长上下文训练数据，提示上下文结构比原始长度更关键。
  • 手术感知： 单帧结构光 + VQ-VAE/U-Net 在 phantom 上展示无同步、视频速率的主动深度重建，但尚非在体或边缘端结果。
  • 机器人学习： POGP 用前缀价值动态停止扩散去噪；EvoHIL 则把人工确认用于更新 reward、动作流和视觉域，两者都在尝试让计算/监督随部署状态变化。EvoHIL 原文
  • 边缘部署： 8GB Jetson 实验把传感、训练收敛、量化与控制周期放在同一预算表中，暴露了 USB/CPU 而非显存成为系统瓶颈的情况。

产品与监管 ​

近 72 小时没有检索到足以扩写的手术机器人产品、监管或远程手术临床新进展。本期保留这一负结果，避免用旧公告填充篇幅。

对 Nathan 当前项目的启示 ​

1. 远程手术：做一张端到端预算账，而不是一张网络延迟表 ​

把一次操作闭环拆成：sensor exposure/capture → preprocess → encode → network → decode → state estimation → policy/assist → safety gate → actuator。每层记录 P50/P95/P99、时钟来源、排队时间、deadline miss 和降级动作。

最小实验与完成标准： 在 10/20/30 Hz 三种控制目标下回放同一组操作轨迹，分别注入网络抖动、相机尾延迟和策略计算峰值；识别每种条件下真正绑定的资源。任何优化只有在端到端 P99 和 deadline miss 同时下降、且动作误差不恶化时才算有效。

2. 手术视觉：验证主动深度的“可失败性” ​

用仿真或 phantom 建立四组干扰：高光、液体/烟雾、组织快速形变、投影—相机标定漂移。除 MAE 外，加入输出置信度、错误深度持续时间和退化触发延迟。

完成标准： 系统必须在预先定义的误差阈值外触发降级；报告 false-safe 次数，而不只报告平均深度误差。若无法可靠发现自身失败，就不能进入自动动作输入链。

3. 机器人强化学习：给动作阶段配置动态计算预算 ​

把任务划分为自由空间、接触前、接触建立、精细操作、退出五个阶段，比较固定去噪步数与动态停止。高风险阶段允许更高预算，但必须受状态新鲜度约束，避免“算得更久却用更旧的观测”。

完成标准： 同时报告成功率、单位动作推理步数、P99 控制时延、接触峰值力和早停误判；在风险阶段的早停误判上限未满足前，不用平均算力节省替代安全指标。

4. AI Native：把目标、约束、证据和被否决路线写成一等状态 ​

为技术调研和设计自动化建立最小 mission record：standing_intent / operational_objective / constraints / verification / accepted_evidence / rejected_routes / operator_decisions / next_mission。上下文恢复时按依赖关系加载，不按目录全量加载。

完成标准： 连续三次跨会话任务中，Agent 能引用上一轮否决路线及证据，不重复无效工作；任何目标修订都能定位到授权人、证据和时间，且不能改写 standing intent。

5. 边缘控制：量化前先做系统 profiling ​

在目标边缘设备上分别采集相机、CPU、GPU、内存带宽、网络、策略和驱动时延；先确认瓶颈，再选择零拷贝、量化、降低分辨率、动作 chunk 或硬件升级。

完成标准： 每项优化提供端到端收益、资源转移和任务级回归三份证据。若 GPU 优化后控制率仍由传感器限制，就停止继续压缩模型，把预算投入采集链或时钟同步。

值得继续跟踪的问题 ​

  1. Argus 的 verifier、memory 和 skill 都可被 runtime 更新时，如何防止验证标准被逐步削弱？
  2. 跨仓库依赖上下文在企业私有代码、多语言接口和运行时配置上，能否保持同样收益？
  3. 主动结构光对高光、血液、烟雾和动态软组织的失效模式，是否能在输出深度前被可靠检测？
  4. 26 Hz 模型推理加入采集、传输、显示和安全层后，端到端帧率与尾延迟是多少？
  5. POGP 的 prefix value 在分布外接触状态下是否会过早停止？需要什么外部安全门？
  6. 动态计算预算如何与网络状态联合调度，避免高风险动作既增加推理又碰上陈旧观测？
  7. ACT 在宽容任务上的 INT8 容差能否迁移到针、线、组织和狭窄通道等高精度任务？
  8. 远程手术端到端预算中，哪个环节最常成为 P99 绑定约束：采集、网络、状态融合还是执行器？
  9. 能否把 Agent 的 mission record 与机器人 episode / intervention record 统一为同一种可审计轨迹结构？
